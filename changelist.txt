DUBROVNIK WORKBENCH - CHANGE LIST
=================================
Newest version first. The version number is set in one place, dubLibs\version.py.
It is shown in both About dialogs and in the help file, and the installer build
(packaging\build.bat) takes it from there too.

To release a new version: change VERSION in dubLibs\version.py, add an entry at
the top of this file, commit, then tag the commit:  git tag v<VERSION>


VERSION 1.4.4                                                      2026-11-13
-----------------------------------------------------------------------------
New:
  * Program panel: "Count across pages". Off (as before), every 256-byte page gets the same
    words, so a counting pattern restarts on each page. On, the counter keeps going from page to
    page (one more board command per page). Scripts: dub.program(..., continuous=True).
  * Keyboard shortcuts to move around the window: Ctrl+1 Serial connection, Ctrl+2 Erase,
    Ctrl+3 Program, Ctrl+4 Read, Ctrl+T Terminal, F6 / Shift+F6 next / previous part. Ctrl+2 to 4
    show the panels first if they are hidden. Also in the View menu.
  * The Terminal puts the cursor on the prompt line when it gets the focus by Tab, Alt-Tab or a
    click outside its text (a click in the text keeps the cursor where you clicked, so you can
    select and copy).
  * The installer puts demo files in Documents\Dubrovnik: demo_srec_1.srec and
    demo_bin_file_1.bin (imageFiles), demo_1_device_check.txt and demo_2_pwr_meas.txt
    (commandScripts). A file that is already there is never replaced, and the uninstaller
    leaves your files alone.
Changed:
  * File > Image Files > Open File starts in Documents\Dubrovnik\imageFiles (made when needed)
    until you open a file from another folder or set a folder in Configure Paths.
  * Configure Paths shows every folder with backslashes (some had "/").
  * Help > Assistant and Preferences > Assistant Settings are hidden until the Assistant's
    credentials are set up. The code is still there.


VERSION 1.4.3                                                      2026-11-12
-----------------------------------------------------------------------------
Fixed:
  * Read failed with "invalid literal for int() with base 16" on devices where command 35 is
    not "Read Status Register 2" (there it is Read Sector Lockdown Registers). The program
    now asks the board (help 35, 5, 31, 1) how the device reads and writes status register 2
    and uses 05 2 or 01 <sts1> <sts2> where needed. Asked once per connection and again when
    a device is detected. A reply it cannot read is now shown with the command and the reply.
  * The default script folders (Documents\Dubrovnik\commandScripts, pythonScripts, myTools) and
    Results and Assistant now always use the same Documents folder. Before, with Documents moved
    to OneDrive, the first three could end up in a different place than Results and Assistant.
  * Windows opened by the program (About, Preferences, Hex View, ...) appear finished and in
    place at once. Before, they were drawn half built, hidden and shown again to colour the
    title bar, and (with the main window on a display whose Windows scale differs from the
    primary display) rebuilt a moment later. Now the window is built hidden, at the scale of
    the main window, the title bar is coloured first, and the window is shown once.
    Nothing is recalculated while a window is open unless it or the main window really moves
    to a display with another scale, or the Windows scale changes.
  * A fixed-size window (Configure Paths, Hex View, About, ...) dragged to a display with another
    Windows scale is now resized to fit its content. Before, its widgets were rescaled but the
    window kept its old size and cut them off.
Changed:
  * Preferences > Configure Paths: the order of the folders is now Command scripts, Python
    scripts, Image files, My tools, Documents, Program tools, Settings.

Added:

    to the start of the typed command; Ctrl+Home goes to the top and Ctrl+End to the prompt line.
  * Read panel: a read of more than 0x1000 bytes is done in pieces in the background; each piece
    is shown in the Terminal as it arrives. The Read button becomes Stop (Esc works too), the status
    bar counts the bytes, and Byte/Word view put a '--- 0x3000 ---' separator above each piece.
  * Program panel, Use Pattern: runs in the background with a progress window (page number,
    address, percent, time left) and a Cancel button. Runs of more than 16 pages print a summary in
    the Terminal instead of a line per page.
  * Erase panel, Chip: a progress window with a Cancel button opens. The expected time comes
    from the capacity in the JEDEC ID (command 9F, third byte); the bar is an estimate.

VERSION 1.2.3                                                      2026-10-15
-----------------------------------------------------------------------------
Added:
  * A command-script template in the Tools menu, to copy and edit: Basic Device Check (read only).
  * help/assistant_reference.md: a compact reference of the dub object, the board commands
    and example scripts, written for an AI model that writes scripts (not loaded by the
    Assistant yet).
  * Help > Assistant Settings: a dialog for the credentials of the experimental Assistant
    (provider, API key or token, base URL, model). The key is stored encrypted for your
    Windows account in %APPDATA%\Dubrovnik\assistant.cfg. Environment variables still work
    for what the dialog leaves empty. Help > Assistant is now always in the menu; without
    credentials it points to the settings.
  * Tools menu: a command script (.txt or .scr) in the tools folder whose first line
    is "# TOOL: name" is listed too, below a divider after the Python tools. It runs
    like File > Scripts > Run Command Script. "# TOOLS:" is accepted as well.
  * Erase, Program and Read panels: hovering over an entry box shows the allowed
    format of its value (hex digits, number of digits, units).

Fixed:
  * Start-up with no COM port, with a COM port that cannot be opened, or with a board whose
    processor does not answer (switched off, not reset): the window now always opens. Before,
    a Retry/Cancel box could repeat for ever, and Cancel quit the program. The problem is now
    reported in the Terminal (and the status bar), and no restart is needed after RESET.
  * A board that stops answering during use: Cancel in the Retry/Cancel box no longer quits the
    program; it only gives up on that command. The box and the Terminal now say what to check:
    press RESET, a valid SD card is inserted, the MCU is functional. Clicking Connect on a board
    whose processor is silent shows the same message instead of the Retry/Cancel loop.
  * Status bar: "No device detected" after the connection text when the board looks for its device
    and finds none (device removed, then RESET: the Terminal says "Failed to detect device"; also at
    Connect). The device name returns when a device is detected again.
  * Status bar: a board that is connected but does not answer shows "Board not responding" after the
    connection text, until it answers again (a command works, or its start-up message arrives after RESET).
  * The COM port list now follows the boards that are plugged in while the program runs (it was only
    refreshed when you opened the list). After swapping boards, Connect uses the new port instead of
    reporting that the old one cannot be opened. A port you typed by hand is left alone.
  * The long serial timeout (for chip erases) is now also set after the first answer of the board,
    so it is in effect after a manual Connect and after RESET on a board that did not answer at first.

Changed:
  * Erase panel: Num. Blocks is now hexadecimal (it was decimal), like the
    other number entries. A value saved earlier as "10" now means 16 blocks.
  * Program panel: Pattern must be exactly 8 hex digits. A shorter pattern was
    padded with zeros by the board; now it is refused with a message.

VERSION 1.2.1                                                      2026-10-13
-----------------------------------------------------------------------------
The Classic edition is discontinued, and the program was restructured inside. What
the Workbench does and how it looks is unchanged. The settings file is not touched.

Changed:
  * The Classic edition (DubrovnikClassic.exe, dubrovnik_workbench_classic.py) is
    discontinued and no longer built or installed. Version 1.2 is its last release;
    it stays available as tag v1.2. Its settings file dubrovnik.cfg is still read
    once, to start the Workbench with the same settings, if the Workbench has none
    yet.

    is an App class (it was one long block of code). The dialogs (Hex Dump, Terminal,

    menus are in files of their own: dubGui\dialogs, dubGui\panels, dubGui\look.py,
    dubGui\menus.py. The menus are described by tables, so an item is found by its
    name and not by its position. The settings are one object
    (dubLibs\settings.py) that loads, checks and saves the settings file. The main
    file went from 2,861 to about 1,000 lines.
  * The help guide no longer mentions the Classic edition.
  * Dead (commented-out) code was removed.
  * Unit tests: 56 (were 38), with new tests for the settings and the entry-box
    checks.


VERSION 1.2                                                        2026-10-13
-----------------------------------------------------------------------------
Programming from firmware files, a hex dump view, Terminal and menu customization,
a datasheet shortcut and helper calls for script writers. This entry covers
everything since 1.1; the notes of 1.1.2 to 1.1.6 below give the details.

New (both editions unless noted):
  * File > Firmware: Open File (Ctrl+O), View File, Program Loaded File (Ctrl+P), a
    grey line naming the loaded file, and Close File. Reads .bin, Motorola S-record
    (.srec .s19 .s28 .s37 .mot) and Intel HEX (.hex .ihex); the format is recognised
    from the content and every line checksum is checked.
  * On Open the Terminal shows a preview in hex-dump layout (first 64 bytes of each
    block, blocks up to 1 KB in full) at the addresses the data will be written to.
    View File opens the whole file in a window with "Go to address".
  * Programming writes S-record and Intel HEX blocks at their own addresses plus the
    Offset and leaves the gaps alone; nothing is erased first. A progress window
    with Cancel (or Esc) is shown, and the programming runs in a background thread
    so the window stays responsive. Program Loaded File also works with the panels
    hidden: it lists the address ranges for confirmation and asks for the Offset.
  * The open-file dialog starts in the folder of the last file opened.
  * Read panel Display Mode "Hex Dump (h)" (address, hex bytes, ASCII) with
    View > Hex Dump settings: bytes per row (8, 16, 32), ASCII column, upper case
    digits, extra space after 8 bytes.
  * View > Terminal: theme, background, text and selection colours, font and size,
    with a preview; Ctrl + mouse wheel changes the Terminal text size.
  * View > Menu text size (Workbench) and a single Hide / Show Panels item that
    shows the action it will do.
  * Help > Datasheet and Datasheet Source: opens the datasheet of the device in the
    status bar (a matching file in docs, or the Renesas web search; the address can
    be changed).
  * Script calls: dub.read_bytes, dub.hexdump, dub.load_image, dub.program_image and
    dub.verify. Unit tests in the tests folder.
  * Experimental AI assistant (Workbench), hidden unless a model is configured; not
    included in the installer.

Changed:
  * File menu: Firmware and Scripts are submenus, Save Terminal Log is a group of its
    own. The old "Terminal theme" submenu and the Panels submenu are replaced.
  * Programming a file, and dub.program_bytes, no longer send the data twice (about
    one third faster).
  * Display Mode is now the same kind of box as the COM port list.
  * Help > Datasheet finds a local file also when the status bar shows an ordering
    suffix after the part number.


VERSION 1.1.6                                                      2026-10-13
-----------------------------------------------------------------------------
Faster, responsive file programming.

Changed (both editions):
  * Programming a file no longer sends the data to the board twice. The extra
    download of the whole file before programming was redundant (every page is
    sent again just before it is programmed), so a file now takes about one third
    less time.
  * Programming runs in a background thread. The window no longer freezes and goes
    "Not Responding" during a long transfer, the progress bar keeps moving, and
    Cancel / Esc react within a page. A communication error during programming is
    reported in the Terminal ("Programming stopped: ...") instead of leaving the
    program waiting.

VERSION 1.1.4                                                      2026-10-13
-----------------------------------------------------------------------------
Programming from S-record and Intel HEX files, a progress window, and the open
dialog remembers its folder.

New:
  * File > Open / Program panel Open (both editions) accepts raw binary, Motorola
    S-record (.srec .s19 .s28 .s37 .mot) and Intel HEX (.hex .ihex) files. The format
    is recognised from the content; line checksums are checked and a bad file is
    refused with the line number. The Terminal lists the loaded blocks.
  * S-record and Intel HEX files are programmed segment by segment at their own
    addresses plus the Offset; the gaps between segments are not touched. In
    "Load from File" mode the Start Address entry is labelled Offset, and the
    pattern, increment and length entries are greyed out. A .bin file is programmed
    from the Offset as before. Nothing is erased automatically.
  * Progress window while a file is programmed (both editions): step, percentage,
    elapsed time and a Cancel button (Cancel or Esc stops between pages; the device
    is then partly programmed).
  * The open-file dialog starts in the folder of the last file opened for
    programming (saved in the settings file as programFolder).
  * dubLibs/firmware_image.py: the file readers as a separate module with no GUI
    code and no dependencies, tests in tests/test_firmware_image.py.

Changed:
  * Length is no longer required to be valid in "Load from File" mode.

New:

    theme follows the window, and Light, Dark and Custom stay as chosen.
  * Display Mode is now the same kind of box as the COM port list (same arrow).
  * The COM port list text uses exactly the size of the widgets next to it.
  * The settings file gains Terminal colour, font and size, menu size and datasheet
    address entries; bad values fall back to the defaults.


VERSION 1.1                                                        2026-10-09
-----------------------------------------------------------------------------
Adds the Documents menu, a much larger help guide and a training guide, and fixes
found while testing on the board (started as 1.0.1; renamed 1.1 for its size).

New:
  * Help > Documents: a submenu that builds itself from the "docs" folder (any file
    type: PDF, PNG, PPTX ...). Used for the board schematic and other reference
    material; drop a file into the folder and it appears. "Open Documents Folder"
    is the last entry. A leading number in the file name sets the order.
  * Help guide: new "Power measurement" section: the eight power domains with their
    shunt resistor, jumper (remove it to measure) and INA230 I2C address, and how to
    measure the device with  pmon 5 start; ...; pmon 5 stop; pmon 5 calc.
  * Help guide: command rules, useful board and flash commands, GPIO pins, pmon
    measurement time and pmoncfg values, and the logic analyzer header pin table.
    Also: About the board (configurations, boot switches), how a flash command is
    built, read-mode notes, more troubleshooting entries and a short glossary.
  * Dubrovnik Training Guide (docs folder, Help > Documents): a searchable
    single-page guide adapted from the 2021 FAE training, with board pictures,
    the system block diagram, SPI/Dual/Quad/QPI timing diagrams, power measurement,
    logic analyzer use and a glossary. The docs folder is now tracked in git.

Fixed:
  * Workbench: the questions and messages of scripts and tools (for example
    Icc Read Measurement) used small standard dialogs; they now use larger
    dialogs that follow the screen scaling.
  * Auto connect at start-up did not show the device in the status bar; it does now.
  * After the board was switched off and on again (or RESET) the status bar did not
    show the device until you disconnected and reconnected. It now follows the board's
    detection message and shows or clears the device by itself.
  * Pasting a command with ">>>", line breaks or invisible characters into the
    Terminal no longer breaks the command line; it is cleaned up.

VERSION 1.0                                                        2026-10-07
-----------------------------------------------------------------------------
First numbered release of both applications. They share the libraries in
dubLibs, the user guide (help\dubrovnik_help.html) and the tools folder:

  Dubrovnik Workbench   dubGui\dubrovnik_workbench.py
                        New edition (CustomTkinter), light/dark appearance.
                        dubGui\dubrovnik_workbench_compact.py starts it with
                        everything about 12% smaller.
  Classic edition       dubGui\dubrovnik_workbench_classic.py
                        The original (tkinter) application, updated. This is
                        the one the installer (packaging) currently builds.

Everything below applies to both applications unless marked "Workbench only".


NEW FEATURES
------------
Read
  * Read modes now work: SPI (0B), Dual (3B), Quad (114) (6B) and Quad (144)
    (EB <address> <mode 00> <count>). Before, the selected mode was ignored and
    every read used the single-SPI command 0B.
  * The Quad Enable bit (status register 2, bit 1) is set for the Quad modes and
    cleared for SPI and Dual. The register is written only when the bit has to
    change, and the result is read back and checked.
  * QPI (444) and Octal are greyed out (not supported yet).
  * Display Mode (Binary / DWord) is read-only (no typing) and remembered.

Scripts (File > Scripts)
  * Run Command Script: a text file of Terminal commands, one per line. '#'
    starts a comment, ';' chains commands on a line, a ';' at the end of a line
    is ignored. Stops at the first "Error:" reply and names the line.
  * Run Python Script: a Python file that gets a ready-made object called "dub":
    dub.send, erase, program, program_bytes, read, sleep, stop_requested, ask,
    confirm, message, output_path, comm, du. print() goes to the Terminal.
    Python errors are shown with their line number.
  * Stop Script (Esc) stops either kind. While a script runs, the panels, the
    Connect button and the Terminal command line are blocked.
  * The Run Script dialogs start in the folder of the last script (dubScripts if
    it exists, otherwise Documents).
  * Python scripts may import modules that sit next to them.

Tools menu
  * Built from the Python scripts in the "tools" folder. A script appears if one
    of its first 20 lines is "# TOOL: Menu name"; optional "# DESCRIPTION:" and
    "# CONFIRM:" lines add a status-bar message and a Yes/No question. The menu
    is rebuilt every time it opens. Drop-in tools need no code change.
  * Dubrovnik Functional Test (tools\functional_test.py): DAC/ADC, five power
    monitors, LEDs, program/erase/read of block 0, V_ADJ steps. Ends with the
    number of checks passed/failed and RESULT: PASS or FAIL.
  * SFDP Program (ATXP032) (tools\sfdp_program_atxp032.py)
  * Icc Read Measurement (tools\icc_read_meas.py): result file saved in
    Documents\Dubrovnik\Results.
  * INA230 Calibration (tools\ina230_calibration.py)
  * The empty placeholder entries (VT distribution, "Other tools") were removed.

File menu
  * New / Save / Save As placeholders removed. Now: Open... (choose a .bin file
    and switch the Program panel to "Load from File"), Scripts, Save Terminal
    Log..., Parameters, Exit (Exit now works).
  * Opening a file that is not .bin, or that cannot be read, shows a message.

Settings and saved values
  * Remembered automatically: window size and position, panels shown/hidden,
    Appearance (Workbench), Terminal theme, last COM port, Auto connect,
    Display Mode, folder of the last script.
  * Saved only on File > Parameters > Save (so that erase/program values never
    come back unnoticed): everything typed in the Erase, Program and Read entry
    boxes, plus the selected block size and SPI mode. Parameters > Load restores
    them, Parameters > Defaults resets the boxes.
  * The Workbench has its own settings file, dubrovnik_workbench.cfg; the classic
    edition keeps dubrovnik.cfg (both in %APPDATA%\Dubrovnik). On its first run the
    Workbench copies the stored values from dubrovnik.cfg.
  * Window size and position are restored when they fit the display; otherwise
    the default size is used.
  * Robust settings files: a missing, damaged or hand-edited file, or a bad value,
    falls back to defaults and never stops the program. A damaged file is kept
    with ".bad" added to its name. Files are saved safely (temporary file, then
    replace).

View menu
  * Panels: Show / Hide the Erase, Program and Read panels together; the window
    shrinks and grows by the height they take, the Terminal keeps its size.
  * Terminal theme: Light / Dark.
  * Appearance: Light / Dark / System (Workbench only). A dark window always has a
    dark Terminal; "Light Terminal" is greyed out while the window is dark.

Help
  * HTML user guide (help\dubrovnik_help.html): Help > Help or F1 opens it in the
    web browser. It contains a quick start, every panel and menu, the Terminal,
    scripts and the "dub" calls, settings, the board command list and
    troubleshooting.
  * The version number in the guide is filled in from dubLibs\version.py when it
    is opened.
  * About: version 1.0; authors Csaba Moldvai (System/Board design, GUI) and
    Eyal Barzilay (Tiberias flash support software).

Terminal
  * Usable without a flash device: after the "No flash device detected" warning
    the cursor and keyboard focus return to the Terminal.
  * Earlier output is read-only (select and copy only). Typing or pasting while
    the cursor is in old text jumps to the prompt line; editing and cutting
    old text is blocked.
  * Debug console messages removed (connection and serial-settings lines,
    "DONE ..." lines, echo of typed commands).

Connection
  * Starting without a board no longer ends the program (it used to exit after the
    "press RESET ... restart the application" pop-up). It starts disconnected; Auto
    connect warns, and the Connect button and the COM port list work later.
  * If the board is switched off or unplugged while connected, the program notices
    within a fraction of a second: the status bar says "Connection to COMn lost",
    the button goes back to "Connect", a note appears in the Terminal, and a running
    script is stopped. Erase, Program and Read then ask you to connect instead of
    failing.

Entry checking
  * Empty or non-numeric entries (address, length, pattern, increment, block
    count) show a message naming the field. No command is sent. Before, an empty
    Pattern or Increment sent a malformed command to the board.


LOOK AND LAYOUT
---------------
Workbench only
  * New look with a colour palette (light and dark), a custom menu bar with a
    larger font, a new About dialog, smaller radio buttons and checkbox, shorter
    entry boxes, wider COM-port arrow, dark terminal by default.
  * Compact launcher (dubrovnik_workbench_compact.py): all widgets 12% smaller.

  * Panels lock to the left and keep their natural width; extra window width goes

LIBRARIES (dubLibs)
-------------------
  * dubrovnik.py: read_mode(), set_quad_enable(), READ_OPCODES, loadDefaultParams
    support, pattern_program() and echo() (called by older scripts but missing from
    the library), set_spi_mode() kept for older scripts.
  * boardcom.py: debug prints removed.
  * New modules: cfgfile.py (settings files), run_cmd_script.py (command scripts),
    run_py_script.py (Python scripts and the "dub" object), tools.py (Tools menu),
    version.py (version number).
  * The applications now put the project's own dubLibs first on the import path.
    Before, a copy named on the PYTHONPATH environment variable
    (C:\MyLibs\Python\Dubrovnik) could be loaded instead of this project's.


PACKAGING
---------
  * packaging\dubrovnik.spec builds BOTH programs into one bundle (dist\Dubrovnik):
    DubrovnikWorkbench.exe (new edition) and DubrovnikClassic.exe (classic edition),
    sharing one runtime, the help folder and the tools folder. Built with
    PyInstaller 6.22.
  * File naming: the programs have no version number in their file name (shortcuts
    and upgrades keep working). The version is stored in each .exe's file
    properties (Details tab), taken from dubLibs\version.py. The installer is named
    Dubrovnik-Setup-<version>.exe.
  * packaging\build.bat uses the project's .venv, reads the version from
    dubLibs\version.py and passes it to the installer script (installer.iss, which
    now installs both programs with Start-menu shortcuts). Set DUB_CONSOLE=1 to
    build with a console window that shows start-up errors.
  * requirements.txt (customtkinter, pyserial) and requirements-dev.txt (adds
    PyInstaller); .venv\ is ignored by git.


KNOWN LIMITATIONS
-----------------
  * Not tested on real hardware (written and tested against a simulated board):
    Dual/Quad reads with Quad Enable handling on every flash type, the Tools
    scripts (functional test, SFDP program, Icc measurement, INA230 calibration),
    and the Python-script and command-script runners. Check the first runs.
  * The INA230 calibration re-synchronises with the board after RESET instead of
    closing and reopening the COM port as the original script did.
  * The Tools menu has no VT distribution tool yet (needs matplotlib and the old
    debugging module); Prog/Verify is a placeholder; QPI and Octal reads are not
    supported; Save Read Data is not implemented.
  * Python scripts run on the window's own thread: a long calculation without a
    dub call (or time.sleep) freezes the window until it ends. Use dub.sleep().
  * A script can erase and program the flash without asking, and a Python script
    can do anything the user can do on the PC. Only run scripts you trust.
  * The installer itself (Inno Setup) has not been compiled yet; the two programs
    were built and started successfully.
