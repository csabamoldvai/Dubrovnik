Dubrovnik Workbench

User guide – version @VERSION@

The Dubrovnik Workbench is the PC front end of the Dubrovnik test board. It lets you erase, program and read SPI flash devices in the board's socket, and gives you a terminal for talking to the board directly (voltage, SPI clock, configuration and raw flash commands).

1. Quick start

  1. Connect the board to the PC with the USB cable and switch it on.
  2. Start the Workbench. If Auto connect is ticked, it connects by itself to the last used COM port. Otherwise choose the port in the Serial Connection panel and click Connect.
  3. Put the flash device in the socket. If the board was already running, press its RESET button so it detects the device.
  4. Use the Erase, Program and Read panels. Each operation prints what it did, and how long it took, in the Terminal.
  5. To keep your entry-box values for next time, choose File → Parameters → Save.
A flash device is not required to use the Terminal. Commands such as volt, freq and config work with an empty socket.

1.1 About the board

Dubrovnik is the flash test board. Its firmware, Tiberias, runs on the NXP i.MX RT1052 microcontroller (it boots from the SD card) and gives a command line over the USB serial connection. The Workbench is a PC application that sends Tiberias commands: every button is a command you could type in the Terminal.

  • Sockets for a 24-ball BGA device and for wide/narrow SOIC devices; an expansion port for a load board or an external device
  • Programmable, software-controlled supply for the device (volt)
  • In-system power measurement of eight supply domains (see Power measurement)
  • Supports SPI, Dual, Quad and (BGA socket) Octal transfers; QPI through the Terminal
  • USB serial connection to the PC, an SD card slot, SDRAM, 1 user button and 6 LEDs; powered from USB or a 5 V supply

The board has three configurations, set by a 0 Ω resistor installation option:

ConfigurationDeviceTransfers
#1 BGA24-ball BGA socket / footprintSPI, Dual, Quad, Octal
#2 SOICWide/narrow SOIC socket / footprint (Standard Flash and DataFlash pinouts)SPI, Dual, Quad
#3 ExpansionExternal device or load board via the expansion portFull xSPI interface

The DIP switches (SW5) select the boot source: XX00 boot from fuses, XX01 serial downloader, 0010 serial NOR (EcoXiP), 1010 SD card (normal use).

The Dubrovnik Training Guide under Help → Documents has pictures of the board and many more examples.

3. Serial Connection

  • Auto connect – connect to the last used port at start-up.
  • COM port – the list is refreshed every time you open it.
  • Connect / Disconnect – opens or closes the port.

After connecting, the status bar shows the port and its settings, for example Connected: COM7 (115200,8,N,1,False).

Only one program can use a COM port at a time. If connecting fails with "access denied", close any other terminal program or a second copy of the Workbench.

If no flash device is found after connecting, a warning asks you to install a device and press RESET. You can still use the Terminal.

Load from File

Click Open (or use File → Firmware → Open File, Ctrl+O) and choose a firmware file. Three formats are accepted, recognised by their content: a raw binary (.bin), a Motorola S-record (.srec, .s19, .s28, .s37, .mot) and Intel HEX (.hex, .ihex). The Terminal lists what was loaded and shows a short preview in hex-dump layout (the first 64 bytes of each block; blocks up to 1 KB are shown in full), at the addresses where the data will be written. Use File → Firmware → View File to see everything. A file with a bad checksum or line is refused with the line number. The next time the dialog opens in the folder of the last file.

The pattern, increment and length entries are greyed out, and Start Address becomes Offset:

  • .bin has no addresses, so the data is programmed starting at the Offset.
  • S-record and Intel HEX carry their own addresses. Each block is programmed at its file address plus the Offset (normally 0). The gaps between blocks are not touched.

Click Program (or File → Firmware → Program Loaded File, Ctrl+P) to start. The menu works also when the panels are hidden: it asks for a confirmation that lists the addresses that will be written, and with the panels hidden it also asks for the Offset. A progress window shows the step and the percentage and the Workbench stays responsive meanwhile; Cancel (or Esc) stops between pages, and the device is then partly programmed. A large image takes minutes (the board accepts 16 bytes per command); as a guide, 100 KB takes about two minutes. The Terminal shows the page-program commands with the time for each page and the total. Prog/Verify is reserved for a later version. To check a file against the flash today, read the range back (Hex Dump mode helps) or use dub.verify in a script.

Flash can only change bits from 1 to 0 when programming. Erase the area first, otherwise the stored data will not match what you programmed. The Workbench does not erase for you.

6. Read

ControlMeaning
SPI / Dual / Quad (114) / Quad (144)How the data is transferred. See the table below.
Start Address (0x), Length (0x)Where to start and how many bytes to read (hexadecimal).
Display ModeBinary (b) shows bytes, DWord (w) shows 32-bit words, Hex Dump (h) shows a hex-editor layout (address, hex bytes, ASCII; see View → Hex Dump). The choice is remembered.
ModeOpcodeDescription
SPI0BFast read, one data line
Dual3BFast read, dual output (1-1-2)
Quad (114)6BFast read, quad output (1-1-4)
Quad (144)EBFast read, quad I/O (1-4-4). The workbench sends mode byte 00.

QPI (444) and Octal are greyed out: they are not supported yet. QPI can be used from the Terminal (38; mode q, back with ff; mode s).

The numbers in the names are the data lines used by the opcode, address and data: 1-1-4 sends the opcode and address on one line and reads the data on four. More lines make a read faster: reading 0x2000 bytes took 1096 µs in SPI, 550 µs in Dual and 392 µs in Quad (1-1-4) in the training example. See How a flash command is built.

Quad Enable is handled for you. Before a read, the Workbench sets the Quad Enable bit (bit 1 of status register 2) for the two Quad modes and clears it for SPI and Dual. It only writes the register when the bit has to change, and checks the result. The bit is non-volatile in most flash devices, so it stays as the last read left it.

7. Terminal

The Terminal shows the results of the buttons above and also accepts commands for the board. Type after the >>> prompt and press Enter. The reply appears below the command.

  • ↑ / ↓ step through the commands you typed earlier.
  • clear (or right-click → Clear) empties the Terminal.
  • Earlier output is read-only. You can click and select it and copy it with Ctrl+C. If you start typing while the cursor is in old text, the cursor jumps back to the prompt line.
  • Messages the board sends by itself, for example after you press RESET, are shown automatically.
  • File → Save Terminal Log writes the whole Terminal to a text file.
  • The Terminal colours, font and text size can be changed under View → Terminal. To change the text size quickly, hold Ctrl and turn the mouse wheel over the Terminal.

Examples

>>> config           show the board configuration
>>> volt 1.8         set the voltage of the device socket to 1.8 V
>>> freq 120         set the SPI clock to 120 MHz
>>> 9f 2             send flash opcode 9Fh and read 2 bytes (the ID)
>>> help all         list every board command
>>> help 3b          show the syntax of flash opcode 3Bh

A command that starts with a hexadecimal number is sent to the flash as an opcode. help <opcode> shows its syntax, and help <command> works for the board commands.

7.1 Command rules

  • Commands are not case sensitive.
  • Flash opcodes and their arguments are hexadecimal; a leading 0 may be left out (6 = 06). Board commands say in their help what they expect; the common ones are decimal: freq (MHz), volt and psset (volts), delay (µs), dummy (cycles) and the pin numbers of the GPIO commands. The buffer commands (pattern, write, dump, cmp) take hexadecimal values.
  • A flash command starts with an opcode: opcode, address, data. A board command starts with a name (freq, pmon, wait, …).
  • Separate several commands on one line with ;. The board reads the whole line first and then runs the commands with the least possible delay in between, which is what you want for timing and power measurements. A semicolon at the end of the line is ignored.
  • The command line has no comments. (# comments work only in command script files.) Do not paste text with explanations.
  • If you paste text that starts with >>>, or that has line breaks or invisible characters (from a presentation, for example), the Terminal removes them and joins the lines with semicolons.
>>> 5; 6; 5; 4; 5      status, write enable, status, write disable, status: three replies (00, 02, 00)

7.3 Flash command examples

>>> 9f 3                                  JEDEC ID: manufacturer, device ID (3 bytes)
>>> 05                                    status register 1 (35 = register 2, 15 = register 3)
>>> 06; 31 02                             write enable, then write status register 2 (non-volatile)
>>> 50; 31 02                             volatile write (lost at power-up or reset)
>>> 65 4                                  read any register (some devices); 71 4 9 writes it
>>> pattern 01234567 0
>>> 06; 2 3000 100; wait 0                program 0x100 bytes at 0x3000 from the write buffer
>>> 0b 3000 100                           read them back
>>> cmp 0 100                             compare (prints Equal! or the differences)
>>> 06; 20 0; wait 0                      erase the 4 kB sector at 0 (52 = 32 kB, d8 = 64 kB, 60 = chip)
>>> b9                                    deep power down (ab wakes the device up)
>>> 06; 2 9000 100; delay 100; 75         start a program and suspend it after 100 µs (7a resumes)
  • Write enable (06) must come before every erase and program. Status register 1 shows RDY/BSY (bit 0), WEL (bit 1) and EPE.
  • Register writes: 50 before the write makes it volatile, 06 makes it non-volatile (the Workbench uses 06; 31 for the Quad Enable bit).
  • Reads with more data lines: 0b fast read, 3b Dual, 6b Quad (1-1-4), eb <addr> <mode> <count> Quad I/O (1-4-4). Quad needs QE = 1 in status register 2. With a mode byte that starts continuous mode, the next read is sent without an opcode: ebc <addr> <mode> <count>.

7.4 How a flash command is built

A flash command has up to four parts, in this order: the OpCode (what to do; every command has one), the Address (where), dummy clocks (idle clocks that some reads need) and the Data (read from or written to the flash). The commands are named after the parts they have:

TypePartsExamples
C-0-0OpCode only06 write enable, 04 write disable, b9 deep power down
C-A-0OpCode and Address20 <addr> erase a 4 kB block
C-0-DOpCode and Data05 read status, 9f 3 read the ID, 01 <data> write the status register
C-A-DOpCode, Address and Data0b <addr> <count> read, 02 <addr> <count> program

The number of data lines used by each part is written after the type: 1-4-4 is one line for the opcode, four for the address and four for the data (Single = 1, Dual = 2, Quad = 4, Octal = 8). With a single transfer rate (SDR) data moves on one clock edge; with a dual transfer rate (DDR) it moves on both.

8. Power measurement

The board measures the current and voltage of eight power domains. Each domain has its own INA230 power monitor, which reads the voltage across a small shunt resistor in the supply line. You choose a domain with its number in the pmon command. You can probe the signals at the shunt resistor or at the jumper pins.

The schematic of the board and the Dubrovnik Training Guide are under Help → Documents. The training guide is searchable and has many more examples.

Measuring the device (DUT)

The device under test sits in domain 5. To measure what an operation draws, put the operation between pmon 5 start and pmon 5 stop on one command line, so that the delays of the PC do not count, and finish with pmon 5 calc:

>>> pmoncfg meas iv                                      what pmon calc prints
>>> pmon 5 start; 0b 0 1000; pmon 5 stop; pmon 5 calc    current and voltage while reading 0x1000 bytes

pmon ... calc prints whatever was set with pmoncfg meas:

pmoncfg measpmon calc prints
icurrent
vvoltage
ppower
ivcurrent and voltage

Set it once before measuring; it stays in effect until you change it.

The pattern is pmon 5 start; ...; pmon 5 stop; pmon 5 calc, where ... is the operation you want to measure: one or several commands, for example a read or a program. For the idle current, use a wait instead of an operation, for example delay 100000 (100 ms).

Another example: the current of an erase, and how long it took.

>>> 06; pmon 5 start; 20 0; wait 0; pmon 5 stop; pmon 5 calc
>>> dvar wait_time                                       how long the erase took (in µs)
  • 06 is write enable. It comes before pmon 5 start, so it is not part of the measurement.
  • 20 0 erases the 4 kB sector at address 0 (opcode 52 erases 32 kB and d8 64 kB).
  • wait 0 waits until the device has finished, so the measurement covers the whole erase. It also measures the time the device was busy: dvar wait_time shows it afterwards, as the Erase panel does.
  • pmon 5 stop; pmon 5 calc stops the measurement and prints the quantity selected with pmoncfg meas (for example the current). The erase time is not part of that printout; get it with dvar wait_time.

The measurement time

The power monitor needs at least one finished conversion. config shows the shortest event as min meas time (us) (9344 µs with the default settings). A shorter event gives an error:

>>> pmon 3 start; delay 5000; pmon 3 stop; pmon 3 calc
Error: 0 samples collected
Min time for measurement in current config: 9344us

Make the event longer, or make the monitor faster with pmoncfg. It applies to the next measurement:

CategoryMeaningAllowed values
avgsamples averaged1, 4, 16, 64, 128, 256, 512, 1024
vstshunt (current) conversion time, µs140, 204, 332, 588, 1100, 2116, 4156, 8244
vbtbus (voltage) conversion time, µs140, 204, 332, 588, 1100, 2116, 4156, 8244
modeconversion modesvt, bvt, sbt (triggered); svc, bvc, sbc (continuous)
measwhat calc printsi, v, p, iv

Defaults: avg 1, vst 8244, vbt 1100, mode sbc, meas i. The time is about avg × vst for current only, avg × vbt for voltage only, and avg × (vst + vbt) when both are measured.

The current of a short operation such as a page program: find out how long it takes, then make the monitor faster than that and start the measurement after the command, so only the busy time counts:

>>> 06; 2 25000 100; timer start; wait 0; timer stop
>>> dvar wait_time                          2154 µs
>>> pmoncfg vst 1100                        shorter conversion
>>> pmoncfg mode svc                        current only
>>> 06; 2 25000 100; pmon 5 start; wait 0; pmon 5 stop; pmon 5 calc

The current of a read: use echo off. A read of 0x4000 bytes (the maximum) is long enough in SPI mode. A Quad read is shorter than the minimum time, so repeat it in the same line: pmon 5 start; eb 0 0 4000; eb 0 0 4000; pmon 5 stop; pmon 5 calc.

The INA230 is made for larger currents. Its inputs carry up to ±10 µA, so it cannot measure deep power down currents (the error is about 20 µA). Use a precision multimeter for those.
  • Use a different number for another domain, for example pmon 1 ... for the adjustable supply. The BGA socket is domain 0, the SOIC socket is domain 5.
  • The Tools entry Icc Read Measurement uses domain 5 and repeats this measurement for several read modes, voltages and clock frequencies.

Probing signals

To look at the SPI signals with a logic analyzer or oscilloscope, use the 2-column header next to the BGA socket (L = left column, R = right column, numbered from the top). The same header serves Quad and QPI.

PinSignalPinSignal
L.1GNDR.1VCC
L.3SCKR.2CS#
L.4GNDR.3DQS
L.5IO0 / MOSIR.5, R.6IO4, IO5 (octal devices)

  • Set the logic threshold to about half of VCC.
  • Make sure the sample rate suits the SPI clock. At power-up the clock is 60 MHz; if the ID reads wrongly on the analyzer, lower it (freq 8) or raise the sample rate.
  • To trigger on an operation, frame it with GPIO 7 (see 7.5) and trigger on its rising edge.

9. Scripts

Scripts repeat a series of operations without clicking. Two kinds are available under File → Scripts:

Menu itemUse it for
Run Command Script...A plain text file of Terminal commands. The simplest way to repeat a setup or a test sequence.
Run Python Script...A Python file. Use it when you need loops, conditions, calculations or want to check the data that was read.

Both show every command and reply in the Terminal, block the panels and the Terminal command line while they run, and need the board to be connected. Stop Script (Esc) stops either kind. The Run Script dialog starts in the folder of the last script you ran.

A script can erase and program the flash, and it starts without asking. A Python script can also do anything else the user can do on the PC. Read a script from somebody else before you run it.

9.1 Command scripts

One Terminal command per line:

# set up the device
config
freq 120            # sets the frequency to 120 MHz
volt 1.9
6; 31 2;            # write enable, then write status register 2
pattern caba0000 1
6; 2 0; wait 0      # page program from the write buffer at address 0
b 0 100             # read 0x100 bytes from address 0
  • Everything after # on a line is a comment. Blank lines are ignored.
  • Several commands can be chained on one line with ;, for example 6; 2 0; wait 0. A ; at the end of a line is ignored.
  • Save the file as .txt or .scr with any text editor.
  • Scripts use the same commands as the Terminal, including flash opcodes. See the command reference.
  • If the board answers with an Error: message, the script stops at that line and the Terminal says which line it was.

9.2 Python scripts

A Python script is an ordinary .py file. The app gives it an object called dub – there is nothing to import – and everything you print() appears in the Terminal.

print("JEDEC ID:", dub.send("9f 2"))
dub.erase(block=4, address=0x1000, blocks=2)
dub.program(address=0x1000, length=0x100, pattern="caba0000", increment=1)
data = dub.read(address=0x1000, length=0x100, mode="Quad (144)")
if "caba0000" not in data:
    print("verify failed!")
CallWhat it does
dub.send(command)Sends a Terminal command and returns the reply as text. An Error: reply raises an error and stops the script; use check=False to handle it yourself, and echo=False to keep the command out of the Terminal.
dub.erase(block=4, address=0, blocks=1)Same as the Erase panel. block is 4, 32, 64 or "chip". Returns the time in µs.
dub.program(address, length, pattern="cafe0000", increment=1)Same as Program with Use Pattern. Pattern and increment may be integers or hex strings. Returns the time in µs.
dub.program_bytes(address, data)Programs a bytes object, for example the contents of a file you opened in the script.
dub.read(address, length, mode="SPI", show=True)Same as the Read panel ("SPI", "Dual", "Quad (114)", "Quad (144)"); Quad Enable is handled as usual. Returns the data as text, without the echoed command. show=False keeps it out of the Terminal.
dub.read_bytes(address, length, mode="SPI")Like dub.read, but returns a bytes object of exactly length bytes and prints nothing. Works whatever the Read panel's Display Mode is. Long reads are done in pieces, so Esc still stops them; an unexpected number of bytes from the board is an error.
dub.hexdump(data, address=0)Text dump of a bytes object in the hex-editor layout (address, hex, ASCII), using the settings of View → Hex Dump. Options for one call: per_row (8, 16 or 32), show_ascii, upper, gap (True or False). Example: print(dub.hexdump(dub.read_bytes(0x2000, 64), 0x2000)).
dub.load_image(path)Reads a .bin, S-record or Intel HEX file (format recognised from its content). Returns an image: image.segments is a list of (address, bytes); also image.size, image.start, image.end. A missing or invalid file stops the script with a message (with the line number for a bad record).
dub.program_image(image, offset=0)Programs every segment of an image (or of the file at a given path) at its address plus offset; the gaps between segments are not touched and nothing is erased first. Returns the total time in µs.
dub.verify(address, data, mode="SPI", limit=32)Compares the flash with a bytes object. Returns a list of (address, expected, actual) for the first limit differing bytes; an empty list means the flash matches.
dub.sleep(seconds)Waits and keeps the window alive. Use it instead of time.sleep.
dub.stop_requestedTrue after Esc. A long loop can check it and finish tidily.
dub.ask(prompt, default="")Asks the user to type a value and returns it as text, or None if the dialog was cancelled. Use it instead of input(), which does not work inside the program.
dub.confirm(question)Yes/No dialog. Returns True for Yes.
dub.message(text)Shows a message and waits for OK, for example for instructions such as "press RESET".
dub.output_path(filename)Full path for a result file: Documents\Dubrovnik\Results\filename. The folder is created if needed. Use it instead of a bare file name, which ends up in whichever folder the program was started from.
dub.comm, dub.duThe board connection and the library object, for scripts written for them directly (comm.send(...), comm.response()). Write comm = dub.comm and drop the lines that connect and disconnect.
  • Esc stops the script at its next dub call or print. Use dub.sleep() for waiting. A long calculation without any dub call, or time.sleep(), freezes the window until it ends.
  • An error in the script is shown in the Terminal with its line number, and the script stops.
  • In the installed program a script can import what is built into Python and what the program contains. Other packages, such as numpy, may not be available.

Examples to start from are in the dubScripts folder: example_device_check.txt and example_python_script.py.

10. Menus

File

  • Firmware – a submenu for programming a file:
  • Open File... (Ctrl+O) – choose a .bin, S-record or Intel HEX file to program and switch the Program panel to Load from File.
  • View File... – opens a window with the whole loaded file as a hex dump, in the layout chosen under View → Hex Dump, at the addresses where the data will be written (file address + Offset; the Offset is in the window title). A heading line starts every block and tells the size of the gap before it. Go to address jumps to a row (an address inside a gap jumps to the next block). The window is a snapshot: after changing the Offset, open it again.
  • Program Loaded File (Ctrl+P) – program the loaded file. It asks for a confirmation that lists the address ranges (with the panels hidden it also asks for the Offset). Nothing is erased first. Greyed out until a file is loaded.
  • Loaded: ... – a grey line showing which file is loaded and its size.
  • Close File – forget the loaded file.
  • Scripts – Run Command Script... runs a text file of Terminal commands, Run Python Script... runs a Python file, and Stop Script (Esc) stops either (see Scripts).
  • Save Terminal Log... – save the Terminal contents as a text file.
  • Parameters – Save stores the values of the Erase, Program and Read entry boxes; Load restores the stored values; Defaults resets the boxes to the built-in values (use Save afterwards to keep them).
  • Exit – close the Workbench.

Tools

Ready-made procedures that run with one click. Each entry is a Python script from the tools folder of the program, run like a Python script: its output appears in the Terminal, the panels are blocked while it runs, and Esc stops it. Some tools ask for confirmation first, because they change the device or the board.

  • Dubrovnik Functional Test – checks the board itself: DAC and ADC, the five power monitors, the LEDs (you check these by eye), a program, erase and read of block 0 of the device in the socket (Adesto/Renesas AT parts only), and the adjustable supply voltage. It ends with the number of checks passed and failed and an overall RESULT: PASS or RESULT: FAIL. Use File → Save Terminal Log to keep the result.
  • SFDP Program (ATXP032) – rewrites the SFDP table of an ATXP032 in the socket and compares it afterwards.
  • Icc Read Measurement – reads the flash in the chosen modes at the chosen voltage and clock while measuring the supply current, and compares the data with the expected pattern. It asks for a device number, a temperature label and whether to paint the memory first. The result is saved as Documents\Dubrovnik\Results\<part> UNIT <n> <temp>.txt. The modes, voltages and clocks are settings at the top of tools\icc_read_meas.py.
  • INA230 Calibration – calibrates the power monitor of the power domains you choose and writes the result to the board EEPROM. Follow the instructions in the dialogs: the sockets of the calibrated domains must be empty and the board has to be reset twice.
  • Open Tools Folder – opens the folder in Windows Explorer.

Adding your own tool. Put a Python script in the tools folder and start it with a line # TOOL: Name in the menu within its first 20 lines. The menu is rebuilt every time it opens, so the new entry appears at once. Optional header lines: # DESCRIPTION: one line (shown in the status bar when the tool starts) and # CONFIRM: question (the tool starts only if the user answers Yes; write \n for a new line).

View

  • Hide Panels (Erase/Program/Read) / Show Panels – one item that does the opposite of the current state: it reads Hide while the three panels are shown and Show while they are hidden. Hiding them gives the Terminal more room, which suits users who work mainly with commands.
  • Appearance – Light, Dark or System (follow Windows).
  • Terminal – opens a dialog for the Terminal look. Theme is Auto (light or dark like the window), Light, Dark or Custom; changing a colour switches to Custom. Pick the Background, Text and Selection colours with the colour button or type a hex value such as #1B1F24. Font lists the fixed-width fonts installed on the PC and Size sets the text size (8 to 32). The preview and the Terminal change as you go; Cancel puts the old look back and Reset to defaults restores the dark theme with Consolas 15.
  • Hex Dump – the layout of the Hex Dump (h) Display Mode of the Read panel: Bytes per row (8, 16 or 32), the ASCII column, upper case hex digits and an extra space after every 8 bytes, with a sample. Nothing changes until OK. A row looks like 00002000  00 00 02 20 19 70 10 03  37 71 00 00 73 79 00 00  |... .p..7q..sy..|; a read that does not start on a row boundary is padded, so the addresses on the left are multiples of the row size. The board still sends plain bytes; the Workbench lays them out. Scripts (dub.read) are not affected. Use a Terminal font that is wide enough: lines that are wider than the Terminal wrap.
  • Menu text size – Small, Normal or Large text in the menu bar and the menus. Use it if the menus look too big or too small on your screen.

Help

  • Help (F1) – opens this guide in your web browser.
  • Documents – the board schematic and other files from the docs folder of the program. Each opens in the program Windows uses for that file type. To add one, put a PDF, picture or presentation into the folder; it appears the next time you open the menu. The menu text is the file name with underscores shown as spaces, and a leading number such as 01_ sets the order and is not shown. Open Documents Folder takes you there.
  • Datasheet – opens the datasheet of the device shown in the status bar. If a PDF whose name contains the part number is in the docs folder (or in %APPDATA%\Dubrovnik\Datasheets) it is opened; otherwise the web address from Datasheet Source is opened in your browser. It needs a connected board with a device.
  • Datasheet Source – the web address used when there is no local file. {part} is replaced by the part number. The default is the Renesas website search (https://www.renesas.com/en/search?keywords={part}); an address without {part} is opened as it is. The address is saved with the other settings, so you can change it if the website moves.
  • About – version and authors.

13. Troubleshooting

SymptomWhat to do
"Serial COM Port Not Found" Connect the USB cable, switch the board on, press RESET and restart the application.
Connecting fails with "access denied" Another program, or a second copy of the Workbench, has the COM port open. Close it.
"Communication Error: Serial Port Timeout" – Retry / Cancel The board does not answer. Check that it is on and press its RESET button, then choose Retry.
"No flash device detected" Insert a device in the socket and press RESET. The Terminal commands (volt, freq, config, ...) still work without a device.
A dialog says an entry "is empty" or "is not a valid hexadecimal number" Correct the entry box it names. Address, length, pattern and increment are hexadecimal; the number of erase blocks is decimal. The command is not sent until all entries are valid.
A Quad or Dual read returns shifted or wrong data The number of dummy cycles probably does not match the flash. Set it with dummy <n> and check the device's data sheet.
Reads show no data (nothing, or only the time) echo off is still set. Type echo on.
A Quad read returns garbage (for example cc cc cc ...) but the SPI read is fine The Quad Enable bit is 0. Read status register 2 with 35; the Read panel sets it for you, but a Terminal command (or a reset after a volatile write) can clear it.
The ID reads 00 00 00 The device may be in deep power down: send ab (exit deep power down), or press RESET. Otherwise check that the device sits in the socket correctly.
A logic analyzer shows a wrong ID Set the logic threshold to about half VCC, and use a sample rate well above the SCK frequency (at power-up SCK is 60 MHz; try freq 8).
"0 samples collected" from pmon calc The measured event is shorter than the minimum time shown by config. Make it longer, or make the monitor faster with pmoncfg (see The measurement time).
"Quad Enable could not be set" The flash did not accept the status-register write, or keeps its Quad Enable bit elsewhere. Use help 31 and help 01 to see the write commands, and the data sheet to find the bit.
A script stops with "error at line N" The board rejected that command. Run it by hand in the Terminal, and use help <command> to see the syntax it expects.
"... is not a valid firmware image" The message names the line and the problem, for example a checksum error. The file may be damaged, or may not be a .bin, S-record or Intel HEX file.
The settings look wrong or the window opens in an odd place Use File → Parameters → Defaults for the entry boxes, or delete the .cfg file listed in Settings.
The Terminal does not accept typing Click on the last line, after the >>> prompt. Earlier output is read-only.

15. Glossary

TermMeaning
Address (A)Where in the memory (or which register) a command works.
CS#, SCK, SI / SOChip select (active low), serial clock, data in, data out of the SPI bus. In Dual and Quad modes the data uses IO0 to IO3.
Dummy clocksIdle clocks between the address and the data of a read, so the flash can prepare the data.
DUTDevice under test, the flash in the socket.
EPE, WEL, RDY#/BSYStatus register 1 bits: erase/program error, write enable latch (set by 06), and ready/busy (bit 0).
JEDEC IDManufacturer and device identification bytes returned by 9f.
JEDEC reset (jrst)Reset of a flash that has no reset pin, with a special pattern on two SPI pins.
OpCode (C)The first byte of every flash command; it says what to do.
QEQuad Enable bit (bit 1 of status register 2 on most devices); it frees IO2 and IO3 for quad transfers.
QPIA mode where every part of a command, the opcode included, uses four lines.
SDR / DDRSingle / dual transfer rate: data on one clock edge / on both clock edges.
TiberiasThe firmware of the board that executes the commands.
Volatile / non-volatile writeA register write that is lost at the next reset or power-up (50 before it) / is kept (06 before it).
XiPExecute in place: a processor runs code directly from the flash.
